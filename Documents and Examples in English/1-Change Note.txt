
2026.11.27
1. [New] Drag to swap two buttons in the key button area.
	- Hold the left mouse button on a button, drag it onto another button in the same tab and release: the names and multi-line contents of the two buttons are swapped. Releasing on an empty button moves the button there.
	- While dragging, a semi-transparent image of the button follows the cursor.
	- When both buttons are empty, nothing happens.
	- When the edit window of either button is open, the swap is not allowed and a message asks you to close the edit window first.
	- Buttons can be swapped while sending; the content that is already being sent is not affected.
	- Swapping works only within the same tab; a button cannot be dragged to another tab.
	- Press Esc while dragging, or release anywhere other than a button, to cancel the drag.
	- Releasing after a drag does not send the button. A plain click (moving less than 5 pixels) still sends as before.
	- When the key file is saved, the buttons are saved in their new positions.

2. [New] Drag tabs to change their order.
	- Hold the left mouse button on a tab label and drag it; a semi-transparent image of the tab follows the cursor.
	- Release on the left half of a target tab to place the tab before it, or on the right half to place it after it. For example, dragging Tab1 onto Tab4: releasing on the left half gives the order 2 3 1 4, releasing on the right half gives 2 3 4 1.
	- Release in the empty space to the right of the last tab to move the tab to the end.
	- Moving a tab does not change the buttons in it, and open edit windows are not affected, so there are no restrictions.
	- Press Esc while dragging, or release outside the tab bar, to cancel the drag.
	- When the key file is saved, the tabs are saved in the new order.

3. [New] Auto sync for key files. Tick "Auto Sync" to the right of "SaveAs". When several TermPlus windows open the same ts file, they stay in sync automatically, with no need to save and load again and again.
	- Local changes are saved automatically. When another TermPlus changes the ts file, the changes are loaded automatically, and you stay on the current tab.
	- Changes to different buttons are merged automatically. When the same button was changed differently on both sides, a window lets you choose which version to keep.
	- When there are many changes, you can choose to use the ts file or the local version. The discarded version is backed up first.
	- When the ts file cannot be reached, a red message is shown in the main window every 5 minutes. Syncing resumes automatically when it is reachable again.

4. [New] Ctrl+Z in the key button area undoes swap, clear, paste and tab delete.

5. [New] The tab right-click menu has a new Duplicate item to copy the current tab.

6. [Change] Deleting a tab: an empty tab is deleted directly; a tab with content asks for confirmation first.

7. [Change] After loading a key file, you stay on the tab you were on instead of jumping back to the first tab.

8. [Change] When the content in a button edit window has been changed but not saved yet, the edit window title shows a *. It disappears after Save.

9. [New] The key file history buttons have a right-click menu with Clear / Clear All, to remove unused entries and free up space in the window.

10. [Change] The button edit window now opens on the right side of the main window, with a height close to the main window.

2026.10.21
1. [Fix] When visa_write(...) / visa_query(...) was used outside the script area (key buttons, single-line send, etc.), the command was cut off at the first closing parenthesis. For example:
	visa_write(CHAM:WAVE_TEXT "(start temp 25C)-(loop count 10)-[(0,25C)-(55,80C)]")
	actually sent only CHAM:WAVE_TEXT "(start temp 25C. Now everything between the first opening parenthesis and the last closing parenthesis is taken, and parentheses and quotes in the command are sent as-is.

2. [Fix] When visa_init / visa_query / visa_write in the script area were written with the command unquoted, the program simply wrapped it in double quotes, so any " or \ in the command produced invalid Python code and an error. Now the unquoted form is treated as raw text; quotes and backslashes inside are escaped automatically before sending.
	Forms that start with a quote and are valid Python expressions are kept unchanged, so existing scripts are not affected, for example:
		visa_write("OUTP ON")
		visa_query("VOLT? " + str(v))

	- A space shorthand is supported, e.g. visa_query CHAM:IP?
	- Anything after the last closing parenthesis (such as a comment) is ignored
	- On a format error, the message shows the text actually received, to help find invisible characters or typos

2026.9.4
1. [New] Two new functions in the script area to run a long, already written multi-line block of commands line by line from a script, without rewriting each line as send_and_get("...") (so there are no more problems with uneven command lengths or trailing spaces):
	- run_button(button name, wait string, timeout, tab_name=None, interpret=True): runs the multi-line content saved in an existing button of the key button area directly; no command file needed. If several tabs have buttons with the same name, specify the tab with tab_name, otherwise a duplicate-name message is shown.
	- send_commands_from_file(file name, wait string, timeout, interpret=True): reads a plain text file line by line and runs it. The file name can be an absolute path, or just a file name, which is then looked up relative to the "Script File" path field in the UI. The file encoding is tried as utf-8, then gbk.
	Both functions process lines exactly like clicking a key button; each line is checked in this order:
	  1. Empty lines and comment lines starting with #            skipped
	  2. wait <seconds>                          really waits, not sent to the serial port
	  3. wait for <string> for <seconds>         really waits, not sent to the serial port
	  4. Custom function commands (show_str / show_date_time / set_port / set_baudrate / connect_serial / close_serial / toggle_serial / open power shell / power shell send / powershell_send / visa_init / visa_query / visa_write / visa_read)  executed, not sent to the serial port
	  5. Everything else                            sent to the serial port, then waits for the wait string
	Also, if a normal command is followed by a wait line, the wait for the wait string on that command is skipped to avoid waiting twice, the same as in the key button send engine. Add interpret=False to turn off this interpretation so every line is sent to the serial port as-is (e.g. when the device itself has a command called wait).
	Other common behavior:
	- Trailing whitespace on each line is removed automatically.
	- If a line does not get its ready signal, the block is NOT aborted. Instead a red warning is written in the main window (with a blank line before and after) stating the source button or file, the original line number in the list, the current progress, the command, what was waited for and the timeout, and then the next line runs.
	- While running, (current line/total lines remaining seconds) is shown at the end of the script line; the countdown looks the same as the existing wait / wait_for countdown.
	- Returns 1 if every wait succeeded and 0 if any wait timed out, so it can be used with if.
	- The Pause and Stop buttons are checked at the start of every line, so even a list of several hundred lines can be stopped immediately halfway.

2. [Added] New file 17-run existing button or command file.txt in Example Scripts. It explains how to write the two functions above, the format of the command list txt, the processing rule for each line, what the progress display and timeout warning look like in the UI, and a pure Python loop that does not depend on the new functions (the script area can use built-in functions such as open() directly, and the os module is available too). The file also points out two common pitfalls: the script area does not support triple-quoted multi-line strings (before the script runs, a line-highlight call is inserted line by line, which breaks multi-line strings, so command lists must be kept in an external txt); and the script runs in a worker thread, so reading UI controls must be wrapped in gui.tk_safe(...).

3. [Added] User Manual additions:
	- run_button and send_commands_from_file added to the custom script function list in 2.3, together with send_and_get, which had always been missing.
	- 1.6 Script area: a sentence pointing to the new functions.
	- New section 2.14 Using existing buttons or command files in a script: parameter meanings, the processing rule for each line, what the timeout warning actually looks like, return values, the progress display while running, and how to write the command list txt.

2026.9.2
1. [Fix] After turning auto save ON, a file might not be created and no message was shown. Before, a warning appeared only when the path or file name was empty; in all other cases open() was called directly, and two kinds of failure were completely silent:
	- When the file name contained a colon, open() raised no error but wrote the log into an NTFS alternate data stream. Explorer and dir show only an empty 0-byte file named after the part before the colon; only dir /r shows the real data stream. The symptom was "the button turned green but there is no file".
	- When the auto save path was a relative path (logs, ., .., C:, C:logs, ~, %USERPROFILE%, etc.) and that folder happened to exist, the file was silently written under the program's current working directory instead of where the user expected. Note that C: is not the same as C:\; the former is a "drive-relative path" that points to the current directory of that drive, and each drive has its own current directory, so the same form gives different results on different drives. In the packaged exe the current working directory depends on the "Start in" folder at double-click, which the user cannot predict.

2. [Improvement] Full validation before auto save is enabled. If any check fails, a popup explains the exact reason and auto save stops; there are no more silent failures:
	- If the file name contains characters Windows does not allow (< > : " / \ | ? *) or control characters, the exact character is shown, with a special note that a colon causes the alternate data stream problem above.
	- The path must be a full absolute path (drive letter plus separator, or a UNC path). Relative paths are always rejected, with an explanation of where they would resolve to.
	- If the path does not exist, this is stated clearly, and the folder is not created automatically, to avoid creating stray folders from typos.
	- If the path points to a file rather than a folder, this is stated clearly.
	- If open() fails, the full absolute path and the path length are shown, to help tell whether it is a permission problem, a path that is too long, or something else.

3. [Improvement] After auto save is enabled successfully, the full absolute path actually written to is shown in the main window, so there is no more doubt about "where did the file go". When the file rotates because it exceeds the size limit, the path of the new file is shown as well.

4. [Improvement] "Max file size" is validated when ON is clicked. If it is empty, not a number (e.g. 1000000MB with a unit, or 1,000,000 with thousands separators), 0 or negative, a popup explains the reason and auto save stops, instead of silently falling back to 10MB. If the value is larger than 20MB, a confirmation box explains that a very large log file may not open in an editor and may make writing and rotation lag; you can continue or cancel.

5. [Fix] When "Max file size" was 0 or negative, the rotation condition was always true, so every 10 seconds the current file was closed and a new one created, producing many small files. Invalid or non-positive values now fall back to the default.

6. [Fix] In the script functions wait_for / wait_for_any / send_and_get / get_future_n_lines_or_till_overtime / get_future_lines_till_str_or_overtime, the increment of the auto-clear lock counter (auto_delete_lock_count) was outside the try block, with several statements in between that could raise an exception (e.g. when over_time was passed as a string by mistake, over_time >= 2 raised TypeError). If an exception was raised there, finally did not run and the lock counter stayed +1 forever, so after that run auto clear never worked again and the main window grew without limit. Now the increment is placed directly before try, and the variables used in finally are given default values in advance.

7. [Fix] The regex matching of send_and_get could return duplicate results. To keep wait_str from being split across two reads, each round the function moved the read start back by len(wait_str)-1 characters, so that text was accumulated twice, and re.findall on it produced duplicate matches (a single-character wait_str moves back 0 characters and is not affected; a multi-character one like "root@" is). Now the regex reads the whole text again from the position after sending to the current end; the accumulated text is only used to check whether wait_str has arrived.


2026.8.26
1. [New] Control character rendering in the main window. New "Display:" drop-down (row4, between "Timeout (s):" and "Auto Scroll") with a tooltip on hover and three options:
	- "Terminal" (default): control characters sent by the device take effect - colors are applied and progress bars refresh in place; the few that cannot be reproduced are written as text like <Esc>[2J instead of showing as boxes.
	- "Show as text": every control character is written out as text (e.g. <Esc>[1m, <CR>, <BEL>) and no effect is applied; used to check what the device actually sent.
	- "Raw (boxes)": old behavior, control characters are inserted into the window as-is and show up as boxes or disappear.
	The setting is saved and restored automatically on program close/start (written to display_mode in TermPlusSetup.ini).
	Besides serial input, everything written to the main window - SSH, PowerShell, script output (show_str etc.), VISA, system messages - uses the same rendering.

2. Details of the "Terminal" option:
	- Applied: SGR colors (16 colors/256 colors/true color), bold, italic, underline, strikethrough, reverse, dim; \r returns to line start and overwrites (progress bars no longer become a pile of new lines); \b backspace; \t expands to 8-column tab stops; ESC[K clear line; ESC[C/D/G move within the line.
	- Silently dropped: NUL padding bytes, ESC[?25h/l cursor show/hide, window-title OSC sequences, ESC(B character set selection.
	- Converted to text: ESC[2J clear screen (the window is not really cleared, to avoid losing history and logs), ESC[1;1H cursor positioning, ESC[A/B cursor up/down, BEL/VT/FF/DEL, etc.; this text is shown in magenta to tell it apart from real content.

3. The main window font is now a monospaced font, so table output and columns overwritten with \r line up. Cascadia Code is preferred; if it is not found, Consolas is used (included in Windows since Vista), and Courier New as the last fallback.
	- Why these three: their bold/italic faces are real separate faces (not synthesized by the system) with the same character width as the regular face, so columns do not drift right after ESC[1m; box-drawing characters (─│┌┐└┘═║ etc.) also take exactly one cell, so tables drawn by the device do not fall apart.
	- Lucida Console, NSimSun, FangSong, MS Gothic and Terminal are also monospaced, but they lack real bold faces and the box-drawing characters above take two cells, so they are not used.
	- Cascadia Code ligatures (-> != == etc.) are not rendered in Tk, because Tk draws with GDI and does not apply the OpenType calt feature. Tested to be pixel-identical to Cascadia Mono, so column calculation is not affected.

4. [Fix] Serial input now uses an incremental UTF-8 decoder, so a multi-byte character (e.g. Chinese) split by a read boundary no longer turns into garbled boxes.

5. [Fix] Escape sequences split by a read boundary are now joined across chunks and recognized correctly even when they arrive byte by byte; if the leftover exceeds 64 characters or is still incomplete after 300ms, it is output literally, so content can never stay hidden forever.

6. [Improvement] The whole rendering process has exception fallback; on an error it falls back to inserting the text as-is, so one exception can no longer terminate the serial receive thread.

7. [Improvement] While a script is running (when wait_for / wait_for_any / send_and_get etc. are using indexes), \r automatically falls back to a newline, the same as the old behavior, to avoid overwriting/deleting characters and disturbing the indexes.

8. [Improvement] The regex match monitor receives clean text with escape codes removed, so rules no longer fail to match because something like ESC[0m sits in the middle; when \r overwrites, a newline is added for the monitor, so line-based rules keep the same meaning.

9. [Improvement] Escaping of control characters when copying text_area content is now consistent with the display logic; ESC is written as <Esc> instead of <ESC>.

10. [Note] The auto save txt contains what is shown in the window, so colors are not saved, and escape sequences converted to text are saved as literal text; in the "Terminal" option tabs have already been expanded to spaces.
